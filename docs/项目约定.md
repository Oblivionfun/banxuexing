一页说清三件事：代码放在哪、照什么写法写、哪些边界不能动。动手前先读；改了架构或写法，同一次提交里改这份文档。

## 二、不变的边界

以下几条是已经定下的产品决策。要改，先和负责人确认，再改代码和这份文档。

1. **一个网站只服务一名学生。** 表里有 `student_id`，给以后多学生预留，但不做账号体系。
2. **只有两种身份。** 家长和老师共用一个查看链接；工作人员用管理口令。不做老师专属入口（2026-11-10 讨论后决定）。
3. **自托管。** Node + SQLite + 本机磁盘，一台服务器。不把外部数据库或对象存储当主存储，对象存储只用来做异地备份。
4. **删除可恢复。** 课程、资料册、文件都是软删除，先进回收站。文件按 sha256 存放，同一份内容只存一次。
5. **自动识别只出草稿。** 群消息识别、大模型整理的结果，必须经过工作人员确认才写入。
6. **先保证微信内置浏览器能用。** 正文不小于 16px，触控目标不小于 44px，手机上不能横向溢出。

## 三、目录与分层

```
app/(site)/          家长端页面，服务端组件为主
app/admin/(panel)/   管理端页面
app/admin/*-actions.ts  管理端的服务端动作（所有写操作）
app/api/             只放需要流式或二进制的接口：上传、文件、ZIP、健康检查
app/s/[token]/       查看链接入口
components/site/     家长端组件
components/admin/    管理端组件
components/ui/       shadcn/Radix 底层组件，按设计 token 重新上了样式
lib/                 业务逻辑
lib/db/              表结构和数据库连接（启动时自动执行迁移）
drizzle/             迁移 SQL，只增不改
tests/  e2e/         Vitest 单元测试 / Playwright 端到端测试
scripts/             部署、备份、恢复、端到端测试启动
docs/                文档
```

依赖方向只能是：页面 → `lib/queries.ts`（读）或 `*-actions.ts`（写）→ `lib/db`。

`lib/` 里分两类：

- **纯逻辑**，不引用数据库：`time`、`lesson`、`group-message`、`summary-parser`、`teacher-profile`、`scheduler`、`labels`、`form`。这些都必须有单元测试。
- **有副作用的**：`queries`、`storage`、`auth`、`ai`、`wecom`。

## 五、写法约定

### 读和写

- **读**：页面直接调用 `lib/queries.ts` 里的函数，不在页面里写 SQL。新增查询时加一行注释，写明用途。
- **写**：管理端的写操作只放在 `app/admin/*-actions.ts`。每个动作固定五步：
  1. `requireAdmin()`；
  2. 用 zod 校验输入，出错时用 `lib/form.ts` 的 `fieldErrorsOf` 返回给表单；
  3. 写库；
  4. `logActivity()`；
  5. `revalidatePath("/", "layout")`。
- 唯一的例外是老师填可上课时间：`app/(site)/availability/actions.ts` 用 `requireViewer()` 校验。
- 一个领域一个 actions 文件。`actions.ts` 已经很长，新领域的动作请新建 `xxx-actions.ts`。
- 带 `"use server"` 的文件只能导出 async 函数，共享的同步工具放到 `lib/`。

### Next.js 16

- 写代码前先读 `node_modules/next/dist/docs/`。
- `proxy.ts` 取代了 middleware。route handler 里的跳转用 `lib/http.ts` 的 `relativeRedirect`，因为经过 nginx 后 `request.url` 是内网地址。
- 页面全部动态渲染：布局设了 `force-dynamic`，没开 `cacheComponents`。不要自己加缓存层。
- `/api/upload` 不经过 proxy，否则请求体会在 10MB 处被截断。所以上传接口自己校验口令。

### 数据库

- **改表**：改 `lib/db/schema.ts`，然后运行 `npm run db:generate -- --name 描述`，把生成的 SQL 和 `meta` 一起提交。
  - 已上线的迁移不改、不删。
  - 新列一律 `notNull().default(...)`，老数据可以直接迁移。
- **日期和时间**：存 `"YYYY-MM-DD"` 和 `"HH:mm"` 字符串，按北京时间理解。计算一律用 `lib/time.ts`，不直接拿 `new Date()` 算日期。
- **枚举**：值放 `lib/enums.ts`，显示文字放 `lib/labels.ts`。switch 的 default 分支用 `never` 兜底，新增枚举值时会编译报错。
- **领域判断写一次**："这节课有没有纪要""有没有课前计划"这类判断都用 `lib/lesson.ts`，不在各处重写。

### 文件

- 上传只走 `/api/upload`：流式接收、核对大小、按文件内容判断类型、sha256 去重。
- 读取只走 `/api/files/[id]`。磁盘路径不出现在页面上。

### 识别与大模型

- 先写规则版：纯函数，配真实样例的单元测试。老师的原话就是回归测试的基准。
- 大模型只用来增强：
  - 没配置或调用失败时，退回规则版；
  - 输出用 zod schema 约束；
  - 日期、时间、科目在服务端再校验一遍。
- 识别结果一律展示在确认页，可以修改；工作人员点保存之前，什么都不写入。

### 组件与样式

- **先复用再新写。** 同样的界面第二次出现，就抽成组件。
  - 管理端：`Field`/`FormSection`（`field.tsx`）、`buttons.tsx`、`SubjectPicker`/`Segmented`（`choice.tsx`）、`PageHeader`。
  - 家长端：`LessonBlock`、`AssignmentList`/`RedPenHeading`、`Markdown`、`SubjectCover`、`TeacherProfileView`。
- **只用设计 token。** 颜色、字号、圆角都用 `DESIGN.md` 里的 token，对应 Tailwind 类如 `text-ink`、`bg-brand-tint`、`border-rule`。不写十六进制颜色。
- **批改红**（`text-mark`、`RedPen*`）只用于老师布置给学生的事：课前准备、作业、下节准备。**学科色**只用于学科标识。
- **文案**：中文，平实，面向家长。
  - 空状态写清下一步该做什么；错误提示写清该怎么办。
  - 不编造老师姓名、成绩或评价。
- **无障碍**：单选组用 `role="radiogroup"`；`<label>` 里不要包其他输入框，否则读屏会把它们一起念出来。

### 代码风格

- import 放在文件顶部。
- 注释只写代码本身表达不了的约束和原因，不写"下一行做什么"。
- 单个文件超过约 400 行，先考虑拆分。

## 六、测试与发布

- **每次提交前**：`npm run typecheck && npm run lint && npm test`。
- **改了页面或流程**，再加跑 `npm run build && npm run test:e2e`。端到端测试会在仓库外的独立目录启动打包后的程序，能发现漏打包的依赖。
- **新功能**：纯逻辑写单元测试，主流程加一条端到端测试。
- **发布**：
  1. 先备份线上数据库；
  2. 运行 `scripts/deploy-server.sh root@113.249.117.200`；
  3. 检查 `/api/health` 和改动的页面。
  4. 命令细节见 `docs/部署说明.md`。
- **改线上数据**：优先用管理端。必须直接改库时，先备份，再补一条 `activity` 记录。

## 七、数据与隐私

- **不进 git**：`.env*`、`data/`、服务器口令，以及老师和学生的个人信息。老师简历只存在线上数据库里。
- **演示数据**：`DEMO_MODE` 生成的演示数据必须标明"示例"。
- **共享服务器**：服务器上还有别人的服务。只动 `/opt/banxuexing`、nginx 的 `banxuexing` 站点、systemd 的 `banxuexing` 服务和 `/etc/cron.d/banxuexing-backup`。

## 八、待办与决策记录

- **企业微信自动同步**：需要先把群换成企业微信建的外部群，并开通会话内容存档（企业自己调用的方式，不走"数据与智能专区"）。落地后复用"导入群消息"的识别和确认流程，不另起一套。
- **异地备份**：还没配置腾讯云对象存储。目前备份和数据在同一块盘上。
- **大模型**：还没配置，识别靠规则。配好 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 后自动启用。
- **域名**：服务器在大陆，用域名要先做 ICP 备案；备案前用 `IP:端口` 访问。
